# Audit AI Assistant — منصة المراجعة الداخلية

منصة عربية (RTL) لإدارة خطة المراجعة الداخلية ومتابعة الإجراءات التصحيحية، مبنية على ملف `Audit_Plan_v2.xlsx`، مع مساعد ذكي مدمج بـ Claude وتحليلات CAATs.

## الصفحات

| الصفحة | المسار | المحتوى |
|---|---|---|
| لوحة التحكم | `/` | مؤشرات السنة، الرسوم، خريطة المخاطر، التنبيهات الذكية |
| خطة المراجعة | `/plan` | جدول العمليات (22 عموداً) + الخط الزمني + التصدير |
| المقارنة والتحليل | `/comparison` | مقارنة متعددة السنوات + تحليلات CAATs |
| تقرير المتابعة | `/follow-up` | سجل الملاحظات (656 ملاحظة) + تقادم + تكرار + خرائط حرارية |
| الإجراءات التصحيحية | `/actions` | دورة عمل كاملة: تذكير، تمديد، تصعيد، إغلاق، فحص أدلة، سجل تدقيق |

## مبدأ التصميم: الحتمي منفصل عن الاحتمالي

في بيئة المراجعة الداخلية لا يجوز أن يكون القرار غير قابل للتدقيق أو التكرار، ولذلك:

- **محرك القواعد** (`client/src/utils/workflow.ts`) يقرّر من مستحق ومن متأخر ومن يُرشَّح للتصعيد — **دوال نقية بلا ذكاء اصطناعي**، تعطي النتيجة نفسها في كل مرة.
- **النموذج اللغوي** محصور في ثلاث مهام، كلٌّ منها **استدعاء واحد بمخرَج منظّم** (لا وكيل مستقل):
  1. صياغة نثر المراسلات — والجدول يُبنى حتمياً في `emailTemplates.ts` فلا يمكن اختلاق رقم أو تاريخ.
  2. استخراج الملاحظات من تقارير PDF — مع اقتباس حرفي ورقم صفحة ودرجة ثقة لكل ملاحظة.
  3. تقييم كفاية أدلة الإغلاق — استشاري بحت.
- **لا تتغيّر أي حالة بلا اعتماد بشري.** المنصة لا تُغلق ملاحظة ولا ترسل رسالة من تلقاء نفسها.

## البنية

```
client/            الواجهة (React 18 + TypeScript + Vite 6 + Tailwind v4)
  api/             دوال Vercel — النواة المشتركة في ملفات _*.js
  public/data/     ملف الإكسل (مصدر الحقيقة، يُقرأ في المتصفح)
server/            خادم Express للتطوير — يركّب معالجات api/ نفسها
```

ملف الإكسل **لا يُعدَّل أبداً**. الإجراءات تُحفظ كطبقة تجاوزات منفصلة فوقه (`actionsStore` + `actionsRepo`)، وصفحة «تقرير المتابعة» تبقى تعرض البيانات الأصلية.

## التشغيل محلياً

```bash
cd server && npm install && npm start
```

```bash
cd client && npm install && npm run dev
```

افتح <http://localhost:5173>. يمرّر Vite طلبات `/api` إلى الخادم على المنفذ 8787.

> المنصة تعمل كاملةً بلا مفتاح API — ميزات الذكاء الاصطناعي وحدها تحتاجه.

## متغيّرات البيئة

محلياً توضع في `server/.env`، وعلى Vercel في **Settings ← Environment Variables**.

### أساسي

| المتغيّر | الغرض |
|---|---|
| `ANTHROPIC_API_KEY` | مطلوب للمساعد الذكي واستخراج PDF وفحص الأدلة |
| `CLAUDE_MODEL` | اختياري — الافتراضي `claude-sonnet-4-6` |

### اختياري: تخزين مشترك

بدونه تُحفظ الإجراءات في متصفح كل مستخدم على حدة (وهذا كافٍ للتجربة). بإضافته تصبح الحالة واحدة لكل من يفتح الموقع.

| المتغيّر | الغرض |
|---|---|
| `KV_REST_API_URL` | رابط Redis بواجهة REST (Upstash أو Vercel KV) |
| `KV_REST_API_TOKEN` | رمز الوصول |

> ⚠️ الموقع عام وبلا تسجيل دخول: تفعيل التخزين المشترك يعني أن **أي شخص يملك الرابط يستطيع تغيير البيانات**.

### اختياري: المشغّل اليومي

يعمل تلقائياً عند تفعيل التخزين المشترك (مجدوَل في `vercel.json` يومياً الساعة 05:00 UTC). يحسب المستحق والمتأخر ويجمّعه حسب المسؤول، ثم يعرضه في المنصة — **ولا يرسل شيئاً**.

| المتغيّر | الغرض |
|---|---|
| `CRON_SECRET` | اختياري — يمنع تشغيل المشغّل من خارج Vercel |

### اختياري: الإرسال الفعلي للبريد

**معطّل افتراضياً.** بدونه تُنسخ المراسلة أو تُنزَّل كملف `.eml` يفتح في Outlook كمسودة.

| المتغيّر | الغرض |
|---|---|
| `RESEND_API_KEY` | مفتاح خدمة [Resend](https://resend.com) |
| `MAIL_FROM` | عنوان المُرسِل من نطاق موثَّق |
| `MAIL_SEND_TOKEN` | رمز سرّي يُطلب من المستخدم قبل كل إرسال |

> ⚠️ **لماذا رمز الإرسال؟** الموقع عام بلا تسجيل دخول. لو تُرك الإرسال مفتوحاً لصار أي شخص يعثر على الرابط قادراً على إرسال بريد من نطاقك — أي مُرحِّل بريد مفتوح يصلح للتصيّد باسمك. الرمز حدّ أدنى للحماية وليس بديلاً عن تسجيل دخول حقيقي. الثلاثة مطلوبة معاً وإلا بقيت الميزة معطّلة.

## النشر على Vercel

| الإعداد | القيمة |
|---|---|
| Root Directory | `client` |
| Framework Preset | Vite |
| Build / Output / Install | الافتراضي |

ثم أضف `ANTHROPIC_API_KEY` في Environment Variables واضغط Deploy.

حدود تقنية مراعاة في الكود: حدّ جسم الطلب في Vercel **4.5MB** (ولذلك سقف الملفات المرفوعة 3MB قبل ترميز base64)، ومعالجة PDF تتجاوز 10 ثوانٍ (ولذلك `maxDuration: 60` في `vercel.json`).

## البناء

```bash
cd client && npm run build
```

## تبديل البيانات

استبدل `client/public/data/Audit_Plan_v2.xlsx` بملف بنفس البنية (5 شيتات سنوية 2022–2026 بـ 22 عموداً و20 عملية لكل سنة، وشيت «تقرير المتابعة» بـ 19 عموداً، إضافة إلى «دليل البيانات» و«القوائم المرجعية») — بلا إعادة بناء.
